## 核心判断

**现有实验范围不变。** 本周最直接的架构竞品是 **RoboArchitect（自动演化执行框架及持久记忆）**、**DiMuRe（诊断驱动的多层次恢复）**、**REA（有预算约束的异步策略路由）**。它们与 DynaHarness、HELM、CRIS-0、LOGIV、RoboDoctor 和 RoboAuto 一起，使“策略＋记忆＋验证＋恢复”这种模块组合难以成为 AURA 的创新点。RoboArchitect 确实公开代码，但实际运行需要多个策略/基准环境、外部模型和 coding agent，**不能因为有 README 就称为低成本可复现**。

**HiLo-WAM** 的双时间尺度预测、**DreamFree** 的未来表征蒸馏、**ARP** 的记忆时效感知异步运行、以及**几何抽象**的局部 RGB-D 证据更新，提供了不同实现路线。它们并不证明所有模块必须同时存在。**LoopQ** 还提醒：压缩减少显存未必降低真实推理时间，干扰下性能可能变差。优先衡量真实物理结果和延迟，而不是扩大架构图。

**继续已批准的 M9a 相机/Vulkan/传感器 I/O 调试**（必须遵守实际暂停状态）。下一个科学实验候选仍是**非特权感知基线验收后的证据时效与任务状态失效处理**；本周**不新增实验**。

## 2. 重点论文：发生了什么、为何重要、能力、AURA 要不要管、如何复现／改进

### A. RoboArchitect — 冻结策略之外自动演化执行框架
**来源：**[arXiv:2610.42141v1，10 月 30 日](https://arxiv.org/abs/2610.42141)、[项目官网](https://roboarchitect-ai.github.io/)、[官方 GitHub](https://github.com/roboarchitect-ai/RoboArchitect)；11 月 5 日核对 README blob `fcaf8b83b2ab8973619e9b1cc73705840763ba82`。

**发生了什么？**Coding agent 读取实际执行轨迹与失败，反复修改策略路由、控制代码和持久记忆，只保留能提高开发集成绩的改动，在未见场景/任务上评估；策略权重不变。作者跨异构测试报告：新场景平均成功率 **9.7%→43.3%**、新任务 **12.7%→40.2%**，并非每个测试都改善。公开代码依赖多套外部基准、策略、工具、模型权重和 **Claude Code**。

**重要性／能力：**自动生成恢复策略、程序性记忆与跨场景迁移，是最直接的创新性竞争者。**AURA：DEEP DIVE，MONITOR/BACKLOG**。**可检验方案：**等兼容 VLA 基线稳定后，在相同运行次数、coding/tool 调用预算下比较原始策略、人工最小修正、单次生成与迭代演化框架；严格保留未见场景、退化测试和工具成本。不能把额外工具/尝试的收益误称为“自主学会了”。

### B. DiMuRe — 诊断驱动的分层恢复
**来源：**[arXiv:2611.04226v1，11 月 3 日](https://arxiv.org/abs/2611.04226)。
**发生了什么？**根据阶段证据和方法前提条件选择直接复用程序或已有恢复技能（含有边界的 VLA 抓取）；程序结束后可由多模态大模型生成修正代码，再做局部效果验证。提出 **LIBERO-Disturb**。在 **801 个预设开发干扰案例**上，作者报告 **Local DiMuRe 77.65%** vs 原程序 **58.68%**，使用相同物理动作步数上限；**Full DiMuRe 81.90%** 额外允许终止后重新规划、**增加动作步数预算**并提前交接，不可把后两者当作完全同预算对照。
**重要性／能力：**直接覆盖“失败归因→选择最小恢复层级”。**AURA：DEEP DIVE，BACKLOG**；不插入 M9a。**可检验：**冻结同一策略和预算，比较直接重试与诊断驱动多级恢复，统计原因正确率、效果验证、误干预和正常案例退化；把大模型/人工预算列清。尚未核对 LIBERO-Disturb 是否具备完整可运行开源环境。

### C. REA — 异步“大脑—小脑”策略路由
**来源：**[arXiv:2610.42053v1，10 月 30 日](https://arxiv.org/abs/2610.42053)。
**发生了什么？**运行中的策略不等待慢速大模型；预先记忆不同策略成功表现，在技能边界使用裁判 gate，采用共享预算的分级升级恢复。作者在 **3000 个 LIBERO-Pro 测试 episode** 上报告 **95.9% vs 最佳单策略 94.7%**，控制步数少 25%、控制时间少 17%；另有样本/策略不同的 RoboTwin 测试。
**重要性／能力：**低延迟多策略调度、恢复代价控制。**AURA：DEEP DIVE，BACKLOG**。**可检验：**在同一个执行策略和预算下，对比判断时机、未被发现的失败、误触发、恢复费用；代码是否可运行尚未确认。

### D. ARP — 显式考虑旧语义记忆的年龄
**来源：**[arXiv:2611.05155v1，11 月 3 日](https://arxiv.org/abs/2611.05155)、[官网](https://arp.insait.ai/)（11 月 5 日显示 **代码/模型即将发布**）。
**发生了什么？**慢速 VLM 异步更新语义记忆，快速动作专家始终看最新相机画面，同时在训练中注入语义记忆过期与执行延迟。作者官网报告移动目标仿真 **51.5% vs 9.5%**；VLM 每 4 秒更新时 LIBERO **79.0% vs 45.3%**。但更广泛 RoboLab 测试为 **20.0 vs 对照 37.9%**，并非全面胜出。
**重要性／能力：**时间戳和过期条件下的实时动作。**AURA：DEEP DIVE（概念），BACKLOG**。**可检验：**新/旧语义记忆 × 实时相机 × 延迟 × 改变指令做交叉对照；物理结果仍需要独立可信的验证，不可简单把“异步”视为可靠。

### E. HiLo-WAM — 同一 WAM 内的双时间尺度
**来源：**[arXiv:2611.05023v1，11 月 3 日](https://arxiv.org/abs/2611.05023)。
**发生了什么？**稀疏长程任务演化视频流与密集短程局部接触流共同生成动作，采用动态去噪和跳步计算。作者报告 RoboTwin 2.0 **93.70%**、RoboDojo 长程任务进度 **17.43**、渐进推理 **2.93 倍加速**，均在其条件下。
**重要性／能力：**任务语义和接触动态需要不同频宽，但不代表必须建两个外部数据库。**AURA：READ→DEEP DIVE，BACKLOG**。**可检验：**把长历史信息与近接触信息分别做消融，评估动作延迟与目标改变后的响应；不更换 M9a 执行器。

### F. DreamFree — 未来表征蒸馏，而非在线生成未来
**来源：**[arXiv:2611.04527v2，11 月 4 日](https://arxiv.org/abs/2611.04527)、[官网](https://harryjo97.github.io/dreamfree/)（代码待发布）。
**发生了什么？**冻结视频教师，用未来表征训练当前图像的预测特征，动作模块推理时不生成未来视频。作者报告 RoboCasa **71.7%**、DROID **50 次现实测试中 64% vs DreamZero 56%**、H200 上约 **91ms/动作块**。14B 主干不适合低成本直接复现。
**重要性／能力：**与 JAM/PDRVLA 一起支持“预测能力可融入快速策略”，不强制使用在线视频世界模型。**AURA：DEEP DIVE 概念，BACKLOG**。**可检验：**同数据、同策略对比仅动作监督／未来特征辅助损失／在线预测器，并完整计入教师和推理成本。

### G. 几何抽象 — 从真实 RGB-D 证据刷新任务状态
**来源：**[arXiv:2611.05058v1，11 月 3 日](https://arxiv.org/abs/2611.05058)、[项目](https://geometric-abstraction.github.io/)、[公开仓库](https://github.com/Spectraorder/geometric-abstraction)（MIT，独立 Python 3.14/MuJoCo 环境；重跑大模型实验还需 Codex 和对应账户）。
**发生了什么？**局部标定 RGB-D 提取物体部分及误差，向高层 LLM 提供 **observed/inferred/unavailable（观测/推断/不可得）**的类型化几何事实；每次物体位姿都重新按证据估计，而不是沿用指令历史。作者报告搭桥堆叠 **28/50 vs 12/50**，重排 **42/50 vs 15/50**，在其条件下环套杆任务时间缩短 33.3%。
**重要性／能力：**与 AURA 的**非特权状态转移验证接口**高度重合，是非常具体的比较基线。**AURA：DEEP DIVE，NEXT-CHECKPOINT 的设计参考，但本周不授权新实验**。**可检验：**待获批后，在同样相机输入下比较纯 RGB-D 验证、带证据状态的几何残差、额外任务状态层；必须测试遮挡/未知/误报完成等情况。可先独立检查仓库现有只读测试。

## 4. 给 02 的架构和创新性含义

**创新性重叠：**DynaHarness + LOGIV + **DiMuRe** 已覆盖依赖和局部恢复；**RoboArchitect** 覆盖自动框架修订与程序记忆；**REA** 覆盖路由和延迟感知升级。因此不能只宣称“智能体＋状态＋验证＋恢复＋记忆”是创新。要在**相同观测、策略、工具预算、未见场景**下证明额外价值。

**挑战 AETHER 工作假设：**DreamFree/JAM/PDRVLA 指向“不在线生成未来也能学会预测特征”；HiLo-WAM 提示多时间尺度联合预测可能仍有价值；ARP/REA 表明异步推理有好处但存在过期语义；显式几何方案表明低成本、可核查观测状态也是强对手。不同实验条件不能直接排列冠军。

**AURA 最有价值的检验：**在**非特权 RGB/RGB-D/本体感知**下，是否能准确区分已经实现的物理效果、证据未知/遮挡、以及此前完成条件因扰动失效，同时不依赖仿真真值和额外有害干预？先证明输入边界可信，再讨论更复杂训练。

## 5. 执行影响结论

**Continue／继续：**仅按现有批准范围推进 M9a Vulkan、渲染、相机、记录与修复；遵守实际操作员暂停和 Core 关卡。11 月 5 日查到工程分支 `06-01/aether-cl-m0` head 为 `cd8185dbe36676c1edd90031e13a105795b617d5`。没有发现更新的原生相机严格中立性审计或非特权验证器验收。冻结 M8 任务、执行器、800 步预算、干扰族与现有评估边界。

**Change now／现在改变：**不修改任何程序、协议或正式 DEC；只更新竞品与创新性解释。**Next checkpoint／下次关卡：**本周**零项新增实验**，保留既定证据时效/状态失效候选，DiMuRe/LOGIV/几何抽象可用于设计对比。**Deferred／暂缓：**自动生成 harness、新 WAM、异步策略训练、RL、平台迁移、硬件购买。**Evidence produced／本次证据：**摘要/作者页面/仓库 README 核对、上游交叉比较、中英文件；**没有**执行 CPU 测试、下载权重、运行仿真/真机或审计出新结果，也没有安排任何实际队员。
