## E1 — REMM: revisable evidence-backed task state

**Primary:** [REMM: Revisable Embodied Memory for Manipulation](https://arxiv.org/abs/2610.12710), submitted October 8. Primary abstract checked.

**Mechanism:** an append-only evidence history supports revisable task conclusions; changed supporting facts withdraw dependent conclusions and trigger bounded repair at verified skill boundaries around a frozen executor.

**Reported evidence:** 51 physical trials, including operator-assisted trials; mean recorded progress increases 57% to 91% in intervention recovery and 43% to 70% in sequence recall against the cited comparison.

**Limit:** these are progress measures, not an all-autonomous task-success rate. Learned dependency discovery, uncontrolled perception and safe mid-skill revision are not established by the abstract.

**AURA use:** candidate evidence/validity semantics after the sensing boundary works. Do not assume a large external graph is necessary.

**Artifact state:** no runnable stack was established in this pass. READ/DEEP DIVE, not ready-to-run reproduction.

## E2 — RESCUE: value of acting on an alarm

**Primary:** [RESCUE: Is This Alarm Worth Acting On? Counterfactual Evaluation of VLA Runtime Monitors](https://arxiv.org/abs/2610.13516), submitted October 9. Primary abstract checked.

**Mechanism:** restore simulator and policy states at checkpoints and compare interventions through task-completion cost, not just failure classification.

**Reported evidence:** 128,340 counterfactual branches involving OpenVLA-OFT and pi0.5 on LIBERO-Spatial/Plus. Under one stop-and-reset cost model, even idealized detection tolerates only about 2.0–3.3% false alarms before unnecessary resets eliminate its benefit.

**Limit:** that tolerance is conditional on the workload, policy, intervention and cost model, not a universal verifier requirement. Recoverability belongs to a state/intervention pair.

**AURA use:** design paired continue/retry/observe comparisons later; preserve policy cache, RNG and controller state during restoration.

**Artifact state:** method-level source checked; no local branch-restoration implementation or native reproduction tested here.

## E3 — TacitVLA: reasoning supervision without current-call text on the action critical path

**Primary:** [paper](https://arxiv.org/abs/2610.17540), submitted October 13; [author project](https://tacitvla.github.io/).

**Mechanism:** the action expert does not attend to generated reasoning for its current call, although reasoning supervision shapes the shared representation. On memory tasks, text entries may be generated during execution for later calls.

**Reported evidence:** controlled comparisons report up to 3.4x lower latency than explicit reasoning with comparable performance; up to 17.1 percentage-point success improvement over a no-reasoning variant at similar latency under the reported conditions.

**Limit:** this does not show that current evidence checks, critical preconditions or emergency stops can safely be delayed. Training-time supervision and inference-time text generation are distinct. Memory-writing latency must fit the physical execution window.

**Artifact state:** the inspected project extract indicated code forthcoming; a complete runnable code/weights package was not verified. Do not label it a ready reproduction.

**AURA use:** compare what must happen before action with bookkeeping that may happen later; test latency and stale-state errors separately.

## E4 — Robota-Embed: action-aware experience selection

**Primary:** [paper](https://arxiv.org/abs/2610.19495), submitted October 14; [author project](https://robota-ai.github.io/robota-embed/).

**Mechanism:** joint vision/language/native-action embeddings align current queries with recorded future continuations. The resulting context supports policy conditioning and task-local context evolution.

**Reported evidence:** 47.33% clip-level and 81.77% episode-level recall@1; selected conditioning comparisons improve success 47.0% to 56.3% on DROID-Sim and 86.4% to 92.8% on a difficult LIBERO subset.

**Limit:** retrieval accuracy is not task success. Query action availability and embodiment/action normalization matter. Task-local memory evolution is not proof of broad cross-task transfer or learned-policy weight improvement.

**Artifact state:** project extract indicated code forthcoming; no working model or dataset download was established here.

**AURA use:** first define an offline episode/continuation retrieval task with held-out episodes, then test downstream use. Exclude future outcomes and evaluation labels from live queries.

## E5 — Fast-VLA: You Only Think Once for Robot Manipulation

**Primary:** [paper](https://arxiv.org/abs/2610.21389), October 15; [official repository](https://github.com/Garfield-kh/FastVLA). README inspected through GitHub; blob `d13fcea6218c60806af2fc1244680ba01832d8e3`.

**Mechanism:** a frozen 4B vision-language encoder processes initial views/instruction once; its KV cache becomes fixed task memory. A smaller actor still consumes current images and robot state. Do not describe it as a robot acting only from its first frame.

**Author-reported results:** RoboTwin clean/randomized 92.46/92.40%; LIBERO/Plus 95.95/79.11%. These are benchmark-specific results, not guarantees under our perturbations.

**Feasibility details from the README:** actor checkpoints and policy-server/evaluation resources are referenced. Setup specifies Python 3.11, Torch 2.11.0 and CUDA 12.8, with simulators in separate environments. The code is described as Apache-2.0 while the frozen base model has separate Gemma terms. Review all artifact terms before use.

**Risks:** fixed semantic context after a changed goal; prefill/peak memory hidden by online-resident metrics; camera/action interfaces differ from the current Panda experiment.

**Status:** documentation inspected, checkpoints advertised, no checkpoint download/import/native run. Reproduction feasibility candidate only; never install into the frozen M9 environment.

## E6 — FastVLA: Task-Conditioned and Temporally Adaptive Visual Token Compression

**Primary:** [paper](https://arxiv.org/abs/2610.22146), October 15; [official repository](https://github.com/jiuyixu25/FastVLA). README inspected through GitHub; blob `90d75c429cf46219852e072fb02081f1000e20ab`.

**Mechanism:** training-free task-conditioned token selection with an adaptive budget. It changes what enters the language backbone each call; it is not the fixed task-cache model in E5.

**Author-reported results:** 35–59% less backbone computation, 9–32% lower simulation action latency and about 20% lower real end-to-end latency in the evaluated settings.

**Feasibility:** README describes OpenVLA/OFT and CogACT integrations, a pruning on/off switch, CPU tests and evaluation commands. It cites roughly 16GB GPU memory for its LIBERO evaluation environment and Python 3.10/Torch 2.2.0. These are author setup requirements, not AURA measurements. Underlying checkpoints and inherited licenses still need checking.

**Risks:** losing small but important visual details, reset/calibration-state leakage, and conflating reduced FLOPs with faster full robot execution.

**Status:** official documentation inspected, code paths advertised; no local tests or reproduction. Potentially bounded intervention after a compatible baseline is stable.

## E7 — LABIT: assembly dependencies and error propagation

**Primary:** [paper](https://arxiv.org/abs/2610.16398), October 12; [official resources](https://irp-hka.github.io/robotic-assembly-benchmark/). Primary abstract checked.

**Mechanism/evidence:** industrial assembly spans operations such as screwing, placement, insertion and snapping with different tolerances; the paper reports primitive, subtask and assembly-level evaluation for its force-position-control baseline.

**AURA use:** adapt the idea of stage-aligned failure/repair annotation, not the entire physical assembly setup. A successfully executed primitive need not leave a valid precondition for the next stage.

**Limit/artifacts:** CAD/protocol resources are advertised; their complete contents and physical reproducibility were not audited here. No hardware acquisition or benchmark implementation is proposed for immediate execution.
