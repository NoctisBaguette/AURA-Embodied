## E1 — REMM：可修订、由证据支持的任务状态

**一手来源：**[REMM: Revisable Embodied Memory for Manipulation](https://arxiv.org/abs/2610.12710)，10月8日提交。原文记录检查过一手摘要。

**机制：**只追加的证据历史支持可修订的任务结论；支撑事实改变时撤回依赖结论，在冻结执行器的已验证技能边界进行有界修复。

**作者报告：**51 次物理试验，包含操作者辅助试验；相较指定对照，干预恢复平均记录进度由 57% 提升至 91%，序列回忆由 43% 提升至 70%。

**限制：**这是进度指标，不是完全自主任务成功率。摘要没有建立依赖关系自主学习、非受控感知或技能执行中安全修订的证据。

**AURA 用法：**传感边界打通后的证据/有效性语义候选；不要假定必须构建大型外部图。

**资产状态：**本轮未确认可运行完整栈。READ/DEEP DIVE，不是已可运行的复现。

## E2 — RESCUE：依据报警行动是否值得

**一手来源：**[RESCUE: Is This Alarm Worth Acting On? Counterfactual Evaluation of VLA Runtime Monitors](https://arxiv.org/abs/2610.13516)，10月9日提交。原文记录检查过一手摘要。

**机制：**在检查点恢复仿真器与策略状态，以任务完成成本比较不同干预，而非仅看失败分类准确率。

**作者报告：**在 LIBERO-Spatial/Plus 上，对 OpenVLA-OFT 和 pi0.5 构建 128,340 个反事实分支。在某一停止并重置的成本模型中，即便理想化检测器，也只能容忍约 2.0–3.3% 误报，否则不必要重置会抵消收益。

**限制：**容忍度取决于任务负载、策略、干预和成本模型，不是所有验证器的普适要求。可恢复性属于“状态—干预”组合的性质。

**AURA 用法：**后续设计继续/重试/观察配对比较；恢复时保留策略缓存、RNG 和控制器状态。

**资产状态：**检查了方法级来源；本轮没有实现本地状态分支恢复，也没有原生复现。

## E3 — TacitVLA：当前动作关键路径不必等待推理文本

**一手来源：**[论文](https://arxiv.org/abs/2610.17540)，10月13日提交；[作者项目](https://tacitvla.github.io/)。

**机制：**动作专家不读取当前调用生成的推理文本，但推理监督仍塑造共享表示。在记忆任务中，可在执行动作时生成供以后调用使用的文字记录。

**作者报告：**与显式推理版本相比，在表现相当的受控条件下，时延最多降低 3.4 倍；与无推理版本相比，在相似时延下成功率最多增加 17.1 个百分点。

**限制：**这不能证明当前证据检查、关键前置条件或紧急停止可以安全延后。训练监督与推理时文本生成是不同过程；记忆写入时间必须适应物理执行窗口。

**资产状态：**原文检查的项目摘录表示代码即将发布；未确认完整可运行代码/权重包，不能标为可直接复现。

**AURA 用法：**区分动作前必须完成的过程和可以稍后完成的记账；分别测量时延与过期状态错误。

## E4 — Robota-Embed：动作感知经验选择

**一手来源：**[论文](https://arxiv.org/abs/2610.19495)，10月14日提交；[作者项目](https://robota-ai.github.io/robota-embed/)。

**机制：**视觉/语言/原生机器人动作的联合嵌入，使当前查询与历史后续动作片段对齐。检索上下文用于条件化策略，并在任务内部演化上下文。

**作者报告：**片段级 recall@1 为 47.33%，回合级为 81.77%；指定策略条件化比较中，DROID-Sim 成功率 47.0%→56.3%，较难 LIBERO 子集 86.4%→92.8%。

**限制：**检索准确率不是任务成功率。查询时是否有对应动作、跨本体动作归一化都重要。任务内记忆演化不证明广泛跨任务迁移，也不等于策略权重得到学习更新。

**资产状态：**项目摘录表示代码即将发布；本轮没有确认可下载工作的模型或数据集。

**AURA 用法：**先定义保留独立测试回合的离线检索任务，再检查下游使用。在线查询禁止包含未来结果和评测标签。

## E5 — Fast-VLA: You Only Think Once for Robot Manipulation

**一手来源：**[论文](https://arxiv.org/abs/2610.21389)，10月15日；[官方仓库](https://github.com/Garfield-kh/FastVLA)。README 通过 GitHub 检查，blob：`d13fcea6218c60806af2fc1244680ba01832d8e3`。

**机制：**冻结的 4B 视觉语言编码器只处理一次初始视角/指令，将 KV cache 作为固定任务记忆；较小的 actor 仍读取当前图像和机器人状态。不能描述为机器人只根据第一帧行动。

**作者结果：**RoboTwin clean/randomized 为 92.46/92.40%；LIBERO/Plus 为 95.95/79.11%。这些只属于相应基准，不保证在 AURA 扰动下成立。

**README 中的可行性信息：**列有 actor 检查点、策略服务器和评测资源；要求 Python 3.11、Torch 2.11.0、CUDA 12.8，仿真器使用独立环境。代码描述为 Apache-2.0，冻结基础模型另有 Gemma 条款；使用前检查全部资产条款。

**风险：**目标改变后的固定语义上下文；在线常驻内存指标未体现预填充/峰值内存；相机/动作接口与当前 Panda 实验不同。

**状态：**已检查文档，来源宣称提供检查点；没有下载、导入或原生执行。仅为复现可行性候选，禁止直接装进冻结 M9 环境。

## E6 — FastVLA：任务条件化、时间自适应视觉 token 压缩

**一手来源：**[论文](https://arxiv.org/abs/2610.22146)，10月15日；[官方仓库](https://github.com/jiuyixu25/FastVLA)。README blob：`90d75c429cf46219852e072fb02081f1000e20ab`。

**机制：**无需训练的任务条件化 token 选择，预算随时间自适应调整；每次调用改变进入语言骨干的信息，不是 E5 的固定任务缓存模型。

**作者结果：**指定条件下骨干计算减少 35–59%，仿真动作时延减少 9–32%，真实机器人端到端时延约减少 20%。

**可行性：**README 描述 OpenVLA/OFT 与 CogACT 集成、裁剪开关、CPU 测试和评测命令。其 LIBERO 环境声称约需 16GB GPU 显存，使用 Python 3.10/Torch 2.2.0。这些是作者配置，不是 AURA 实测。底层检查点与继承的许可仍需核实。

**风险：**删除微小但重要的视觉细节；重置/校准状态泄漏；把 FLOPs 降低误当成整机执行变快。

**状态：**检查过官方文档，代码路径由来源列出；未执行本地测试或复现。兼容基线稳定后，可能成为有边界的干预。

## E7 — LABIT：装配依赖与错误传播

**一手来源：**[论文](https://arxiv.org/abs/2610.16398)，10月12日；[官方资源](https://irp-hka.github.io/robotic-assembly-benchmark/)。原文记录检查过一手摘要。

**机制/证据：**工业装配包含不同公差的拧紧、放置、插入、卡扣等操作；论文以力—位置控制基线在原语、子任务和整套装配层级评估。

**AURA 用法：**借鉴按任务阶段标注失败/修复的思路，而不是重建整套物理装配平台。某原语成功执行，不代表为下一阶段留下了有效前置条件。

**限制/资产：**来源宣称提供 CAD/协议资源，但本轮未审计完整内容和物理复现条件。当前不建议采购硬件或完整实现该基准。
