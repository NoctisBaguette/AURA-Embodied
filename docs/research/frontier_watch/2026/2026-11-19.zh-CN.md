## 核心建议

**继续既有 M9a commissioning，允许不同技术路线并存，把低成本的场景/本体迁移作为更强的科学问题。**本周 AURA 独立发现的最重要研究是 **InteractVLA（11月17日）**：让冻结的流式 VLA 成为**可被几何目标引导、动作块可供观察并可修正**的工具。**CoBoVLA（11月17日）**提出小规模、可解释的步骤/动作代码；**MARS（11月14日）**使用阶段专属技能路由；**ThinkWAM（11月16日）**和**Task Convergent Flow Matching（11月17日）**讨论未来预测、物理进展约束的真实控制收益。这些是**互相竞争的备选方案**，不是要同时加入 M9a 的功能清单。

外界关于规划、记忆、执行监督和恢复的成果增多，不意味着应放弃 AURA 已积累的 M0–M8 实验基线，也不能仅凭“规划器+记忆+验证器+恢复”架构图声称创新。我们真正可能贡献的是**在未见过的物体、布局、数据、传感器和机器人条件下，通过低适配成本保持物理任务效果**。不同论文使用不同任务、特权信息、训练/推理预算，其成功率不能直接互相排名。

**工程授权：**Core 连续性 **v0.3** 与 [11月12日恢复许可](https://github.com/NoctisBaguette/AURA-Embodied/blob/main/docs/research/coordination/BAGUETTE_M9a_Resume_Authorization_2026-11-12.md) 只解除既有 M9a Vulkan/渲染/相机/传感器 I/O commissioning 及记录修复的暂停。11月19日直接检查 [06-01/aether-cl-m0](https://github.com/NoctisBaguette/AURA-Embodied/tree/06-01/aether-cl-m0) Git ref，确认为 **cd8185dbe36676c1edd90031e13a105795b617d5**；阅读了[相机 I/O 记录](https://github.com/NoctisBaguette/AURA-Embodied/blob/06-01/aether-cl-m0/docs/research/experiments/AURA_M9a_Camera_IO_Commissioning_v0.1.md)。文档记录旧报告层错误和修复方案，**没有证明新的完整原生渲染中立性或非特权验证器验收结果**。尚未批准新一轮 M9a 科学评估。M8/M9a 的任务、控制器、恢复、评分器、力条件、阶段上限、种子、干预和**800动作预算**保持冻结。仓库文档不代表服务器实时健康检查。

## 2. InteractVLA：冻结策略也可以作为可引导的工具（NEW，11月17日）

**来源：**[arXiv:2611.22584 v1](https://arxiv.org/abs/2611.22584)、[项目](https://lingwupro.github.io/InteractVLA/)、[官方代码](https://github.com/LingwuPro/InteractVLA)。11月19日读 README，blob **b025ab3ef18260f718215acb1cbe1d05dbd02649**，链接了实际 PyTorch/JAX 几何引导、反馈/运行时代码和测试。**未在 AURA 本地安装。**

**改进与能力：**上层智能体指定末端目标位姿，借助可微“命令→位姿”映射在采样时引导**冻结的流式 VLA**；柔性时间对齐允许合适的动作步骤才完成目标位姿，避免强迫固定时刻到达。动作块和相机投影返回上层智能体，可用于识别空间偏差、重定目标、局部编辑。兼容性检查可拒绝目标。这是**双向几何策略接口**，比单纯调用语言指令更有信息量。

**证据与局限：**作者报告 **LIBERO-Plus 99.4%、RoboDojo 48.62%、RoboCasa365 89.4%**；仓库明确部分比较采用不同的基准条件和上层智能体后端，所以不能解释为同等成本/特权下的直接优越性。适配还要求动作专家支持相应梯度、坐标系/归一化/夹爪动作兼容。所谓“兼容评分”不是物理任务成功概率。

**对 AURA 的意义：**直接对准可复用 VLA、布局变化和无需整网重训的适配。不过 WP3 应先做**只读源代码接口审计**，列出观测、动作单位、世界/基座/末端坐标系、动作块频率、相机标定、模型后端和资源成本。未来**只有 Core 批准**时才在同一冻结策略下比较原始策略、几何引导和反馈修正，测目标域物理成功、不必要修正、墙钟/API成本和新场景适应。**DEEP DIVE；MONITOR/BACKLOG**，不替换 M9a 的执行器。

## 3. CoBoVLA：小型且可解释的语言与动作代码（NEW，11月17日）

**来源：**[arXiv:2611.22395 v1](https://arxiv.org/abs/2611.22395)。

**机制：**语言指令→离散**步骤码**，视觉规划→**动作码**，语言无关的 actor 执行动作；总规模约 **250M 参数**。作者报告 **LIBERO Goal 91.4%、LIBERO-Para 81.1%**，在指定硬件下约 **17ms/控制步**。本周**未核实权重/代码可下载**，也没有在 AURA 硬件测得时延。

**价值与可比较问题：**低成本部署和可解释错误来源，可能比增加巨大模型更符合我们资源。语言改写鲁棒性不等于场景、相机或机械臂迁移。未来在同样训练数据/推理预算下比较普通小策略、离散代码路线和简单的指令规范化基线，区分语义理解错误与动作控制失败。**DEEP DIVE / WATCH 资产；MONITOR/BACKLOG**。

## 4. MARS：按操作阶段调用专门技能（NEW，11月14日）

**来源：**[arXiv:2611.19324 v1](https://arxiv.org/abs/2611.19324)。

冻结通用 VLA 加上循环/语义阶段判断器，把任务路由给通过 RL 训练的原子技能。这是**策略/技能路由**，不是任意模块无条件互换。作者报告阶段分类 **macro-F1 90.47%**（其轨迹标注条件）及模拟管件运输成功率 **20.04%→85.67%**；标签、技能训练和切换本身有成本。阶段识别错误可能导致危险切换。

**AURA 问题：**分阶段执行是否在未见场景下优于冻结端到端策略和廉价规则路由？应测阶段误判、切换时延、失败、目标域示范/RL成本。**READ→DEEP DIVE；BACKLOG**，不授权训练新技能。

## 5. ThinkWAM：在线预测的收益要覆盖时延（NEW，11月16日）

**来源：**[arXiv:2611.21258 v1](https://arxiv.org/abs/2611.21258)。

用**提出动作→依据预测未来重新思考→修正动作块**的在线循环；与 JAM/PDRVLA/DreamFree/ReLAP 一类“预测只用于训练监督、部署可移除预测器”是不同路线。作者报告部分模拟设置下生成约 **153–165ms** 和多项任务指标，但 AURA 尚未测真实机器人端到端时延。

**对 AURA：**未来应将在线世界预测、仅训练期物理潜特征、廉价状态验证器以及完全不加预测作**公平备选**。比较物理效果正确性、复杂接触失败和扰动时反应时间，而不是只比较视频逼真度。**DEEP DIVE；BACKLOG**。

## 6. Task Convergent Flow Matching：运动必须对任务真的有进展（NEW，11月17日）

**来源：**[arXiv:2611.22609 v1](https://arxiv.org/abs/2611.22609)。

用并行**物理模拟 rollout**验证候选动作块是否满足“任务进展漏斗”：允许有限的暂时退步，但总体要向目标收敛；使用 CMA-ES 及先验分布约束寻找合适的生成种子。作者报告 PushT **31.3%→88.5%**、三积木堆叠 **77%→86%**。

**AURA 价值与边界：**提醒我们区分“动作看起来合理/控制器结束”与“实际物理状态达成并维持”。但该算法**需要物理模型和任务进展参考指标**，并不是只看 RGB-D 的非特权验证器。可以将“净进展、卡住、虚假完成、先前支持条件被推翻”纳入**离线评价设计**，而评分真值不能偷传给实时验证器。**DEEP DIVE 评价方法；BACKLOG**。

## 7. ReLAP、PriDex：数据与本体迁移（NEW，11月16–17日）

**ReLAP：**[arXiv:2611.22077 v1](https://arxiv.org/abs/2611.22077)，11月17日。无需动作标签的视频预训练出具有动作信息的循环潜特征；推理部署阶段可以去掉未来预测头。作者报告 LIBERO **97.9%、LIBERO-Plus 70.0%**，仍使用大量训练资源；**本次未核实可执行权重**。挑战“必须在线运行世界模型”的假设，值得研究训练信息与部署成本的关系。**READ→DEEP DIVE；BACKLOG**，不启动大规模训练。

**PriDex：**[arXiv:2611.21908 v1](https://arxiv.org/abs/2611.21908)，11月16日。从人手/物体相对运动形成带置信度的先验，再通过仿真强化学习迁移到某些双臂操作。这里的贡献取决于**重定向、标定、仿真现实偏差和目标域适配成本**，不能说随意换机器人就零成本成功。**READ/WATCH；BACKLOG**。

## 8. JointGV、ScaleVLA：资产与算力界限（NEW，11月16–17日）

**JointGV：**[arXiv:2611.22543 v1](https://arxiv.org/abs/2611.22543)，11月17日。结合图与视觉残差修正长期动态预测，作者在部分控制任务报告状态误差降低，不能推广为完整的操作系统可靠性。论文声称的 [GitHub 仓库](https://github.com/JasonLvernex/Joint_Graph_Vedio_Latent_Dynamic_World_Model) 检查时返回 **404**；**不能声称可复现代码公开**。**READ，有界预测参考；暂无可用复现资产。**

**ScaleVLA：**[arXiv:2611.21607 v1](https://arxiv.org/abs/2611.21607)，11月16日，[官方仓库](https://github.com/GalaxyGeneralRobotics/ScaleVLA)。把超大型 **552B 冻结骨干**用于动作专家，作者报告部分低数据/分布变化优势；对小团队来说训练/部署资源门槛极高。可作为大模型迁移对照，**不是当前要重训的基线**。**READ/WATCH；BACKLOG**。

## 9. 上游已发现、AURA 本周重新阅读一手来源的研究

**PEAR / 原生 robot-use RL：**[2611.18562（11月13日）](https://arxiv.org/abs/2611.18562) + [官方代码](https://github.com/mit-han-lab/pear)。27B推理模型通过**仅仿真机器人使用强化学习**生成位姿命令；作者报告 LIBERO **1.6%→74.4%** 和特定双臂物理实验 **60%**。仓库 README 确有 veRL/Ray/GRPO 以及 **H100/H200/GB300 训练、RTX5090/GB300模型服务**说明。它仍依赖底层机器人控制器；“不需要特制推理 harness”不等于“没有控制系统”。**DEEP DIVE，但不启动完整重训。**

**Reins / 有条件执行与并发观测：**[2611.16632（11月12日）](https://arxiv.org/abs/2611.16632)。把原子机器人动作变成条件守卫链；同时有另一个观测者持续补充场景变化，减少模型思考期间信息过时。作者报告五种实机双臂任务 **88%**；**可运行代码尚未确认**。未来应比较无守卫、有守卫、有守卫+并发观察，以及误暂停、错误继续和全部墙钟/工具成本。**DEEP DIVE / WATCH 代码**。

**Agentic-Teacher / 用首错点示范补训 VLA：**[2611.17394（11月12日）](https://arxiv.org/abs/2611.17394)。Agent定位 VLA 失败状态，生成验证过的成功续接、扰动/筛选训练样本，再更新 VLA；部署时**不需要运行该 agent**。作者报告 LIBERO-10 **79.4%→87.8%**，部分 RoboCasa **0%→30%**；仿真证据，全部训练流水线资产未核实。未来同等新增数据比较随机完整回合与首错点续接，评估跨场景和旧技能遗忘。**DEEP DIVE；BACKLOG**。

**STVLA / 几何感知的时序记忆：**[2611.16589（11月12日）](https://arxiv.org/abs/2611.16589)。在遮挡与视角变化下组合几何特征和历史记忆；实机结果是作者报告，增加的预训练几何信息也可能解释一部分增益。应控制记忆、延迟和几何模型预算，对照单帧、外观记忆、几何记忆及联合。**READ→DEEP DIVE；BACKLOG**。

**本体锚定与传感偏差：**[2611.17658（11月13日）](https://arxiv.org/abs/2611.17658)。示范时的机器人状态可让策略在**开环**对物体测量随机噪声不那么敏感，但作者筛选通过的**15个闭环策略全部比开环公式预期更易受持续偏移影响**。这是合成高斯噪声仿真，不是真实相机测试，**不能据此宣布 M9a 已失效**。一个廉价的后续负对照是“随机观测噪声 vs 持续标定偏移”，分别测开环动作反应和闭环任务成功率。**READ→DEEP DIVE；BACKLOG**。

## 10. AURA 架构判断与可推翻的选项

现有 [AURA 架构](https://github.com/NoctisBaguette/AURA-Embodied/blob/main/ARCHITECTURE.md) 本就采用**能力与接口框架**，不要求全部学习功能都独立模块。可保留多条技术组合：

1. **冻结VLA+几何接口：**InteractVLA（需满足动作梯度、坐标/频率等严格前提）。
2. **小型语义代码或阶段路由：**CoBoVLA、MARS（可能增加可解释性，也可能增加切换错误和训练成本）。
3. **把机器人操作直接学进推理模型：**PEAR（严肃对照，但计算昂贵，底层控制仍必要）。
4. **有守卫的外围工具执行：**Reins（外部证据与动作约束可能优于全模型重新训练）。
5. **仅训练期预测与在线预测：**ReLAP/JAM/PDRVLA 对比 ThinkWAM、Task Convergent 和小型验证器，谁更好需要实测。
6. **首错点定向补训：**Agentic-Teacher（与在线恢复不同）。

**不能拿“有 memory + verifier + recovery”当成原创性充分依据。**DynaHarness、RoboArchitect、Reins 已覆盖其中部分能力；DynaHarness **本周未重新核对一手证据**，仅保留此前已知的比较地位。AURA 应证明：**在廉价基线也有机会赢的条件下，某机制能否在未见环境/数据/本体下保持真实物理效果，且适配成本合理**。

迁移测试必须固定并说明源/目标物体、任务、布局、相机/坐标/机器人、数据分布、可用演示和训练、延迟与最终成功。**接口能调通或模型体积变小，不能自动证明场景迁移。**

## 11. HQ / Core / 队友交接

本周只扩展原有 **WP1–WP4**，不新建团队任务或自行分配人员；详见[完整中文交接](2026-11-19-handoff.zh-CN.md)及[英文](2026-11-19-handoff.md)。

- **WP1：**把 InteractVLA、CoBoVLA、PEAR、Reins 与 DynaHarness/RoboArchitect、廉价对照放在同一有版本的 prior-art 表；比较真实允许输入、策略是否冻结、动作接口、资源成本和反例。
- **WP2：**只读/离线准备相机标定、证据时间/有效性接口，利用噪声论文设计未来的持久偏移负对照；**不改当前 M9a**。
