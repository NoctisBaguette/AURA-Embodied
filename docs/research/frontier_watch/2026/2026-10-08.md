## Executive signal

The two independent watches found surprisingly little exact duplication but converged strongly on the same system-level problems.

The combined working hypothesis is:

> **A robust manipulation agent may need long-horizon task structure and explicit memory above a fast physical policy, bounded predictive models around action selection/verification, and a recovery loop that turns diagnosed failures into reusable experience.**

This is not a final AETHER architecture. It is a set of increasingly testable hypotheses.

## 1. DynaHarness — direct competitive signal for AETHER

### What happened?

The Embodied-AI watch identified DynaHarness as a high-priority system that places a frozen/strong policy inside a dynamic physical-governance layer with command grounding, monitoring, refusal/substitution, bounded execution, failure attribution, and replanning.

### Why does it matter?

This overlaps with territory AETHER might otherwise have treated as distinctive:

```
policy
+ verification
+ execution monitoring
+ failure attribution
+ recovery/replanning
```

AURA therefore cannot defend novelty by simply assembling those components around a VLA.

### What capability does it represent?

- execution governance;
- verification;
- failure attribution;
- recovery/replanning;
- integration of learned and analytic capabilities.

### Does AURA care?

**Very high.**

DynaHarness should be treated as a competitor/comparison point, not merely supporting evidence for AETHER.

### Possible reproduction/improvement?

First reproduce/compare the core claim:

```
raw policy
vs.
one-step replanning
vs.
governed execution
```

Then test candidate AURA extensions:

- richer diagnosis across perception/task-state/policy/contact/control/environment causes;
- hierarchical minimum-cost recovery;
- persistent memory of failures and recoveries;
- recovery-to-learning;
- bounded predictive verification;
- embodiment-aware execution interfaces.

**Decision:** **DEEP DIVE + REPRODUCE**

**Architecture action:** Branch 02 should perform an explicit AETHER ↔ DynaHarness comparison before stronger novelty claims are made.

## 2. Planning Limits of Latent World Models — bounded prediction over monolithic imagination

### What happened?

The Embodied-AI watch found evidence that action-conditioned latent world models remain useful mainly over limited practical horizons, and that nearby subgoals plus feedback/re-observation can outperform trying to imagine the entire task to completion.

### Why does it matter?

It challenges the assumption:

```
world model = long-horizon planner
```

A more defensible working decomposition is:

```
task reasoning
-> nearby subgoal
-> short-horizon physical prediction
-> action ranking / verification
-> execute
-> reobserve
```

### What capability does it represent?

- bounded physical foresight;
- action selection;
- predictive verification;
- hierarchical planning.

### Does AURA care?

**Very high.**

This directly affects how AETHER should think about world models.

### Possible reproduction/improvement?

Compare:

- no prediction;
- short-horizon action ranking;
- short-horizon MPC-style replanning;
- long-horizon imagination;
- nearby-subgoal + bounded prediction.

Measure task success, prediction horizon, compute cost, and failure localization.

**Decision:** **DEEP DIVE**

## 3. RoboCoach — failure localization should control data acquisition

### What happened?

RoboCoach uses a world model/progress judge to identify the first failing subtask and uses aggregated failure evidence to target new demonstrations and expert updates.

### Why does it matter?

It connects:

```
verification
-> failure localization
-> data acquisition
-> targeted adaptation
```

rather than treating new demonstrations as an undirected scaling problem.

### What capability does it represent?

- progress tracking;
- failure diagnosis;
- targeted supervision;
- experience-driven adaptation.

### Does AURA care?

**Very high.**

### Possible reproduction/improvement?

Use a 3-stage simulation task and intentionally weaken one skill.

Compare:

- random extra demonstrations;
- full-task extra demonstrations;
- demonstrations targeted at the first failing skill.

Measure:

- final task success;
- added-data efficiency;
- diagnosis accuracy;
- whether unrelated skills regress;
- transfer to another task that reuses the repaired skill.

**Decision:** **DEEP DIVE + REPRODUCE**

## 4. FailBank — recovery is not learning

### What happened?

FailBank turns selected useful runtime corrections into persistent policy updates instead of using a correction only once.

### Why does it matter?

A robot that recovers today but repeats the same failure tomorrow has recovery capability but weak learning autonomy.

AURA should separate:

```
Recovery:
Can I survive this failure?

Learning:
Will this experience reduce future failure?
```

### What capability does it represent?

- failure memory;
- selective continual learning;
- runtime feedback reuse.

### Does AURA care?

**Very high.**

### Possible reproduction/improvement?

Compare:

- recovery only;
- store-all recovery episodes;
- selectively admitted failure/recovery memory;
- selective policy or skill update.

Measure repeated-failure rate and catastrophic regression.

**Decision:** **DEEP DIVE**

## 5. Memory is becoming functionally decomposed

The combined watches exposed several different things currently called "memory":

- **D²-VLA:** persistent history + fast recent-state memory;
- **FineART:** explicit task/subtask progress;
- **RoboICL:** episodic interaction memory;
- **Optimus-R:** reusable query-skill memory;
- **FailBank:** failure/correction memory.

### AURA interpretation

Do not freeze memory as one buffer or one database.

Candidate research distinctions:

```
working/recent-state memory
task-state/progress memory
episodic interaction memory
failure/recovery memory
skill/procedural memory
semantic/world knowledge
```

The important question is which distinctions improve manipulation reliability and adaptation.

**Decision:** **DEEP DIVE conceptually; experiment through controlled ablations**

## 6. World models are becoming action-relevant rather than visually impressive

The combined watches found convergent evidence from:

- Magic-W0;
- CtrlWAM;
- ATI-VLA;
- RoboCoach;
- Planning Limits;
- functional world-model benchmarks.

### AURA interpretation

A useful manipulation world model should represent or predict something that changes a physical decision.

Current principle:

> **Evaluate world models by decision value, controllability, physical consistency, and verification utility — not future-image quality alone.**

**Decision:** **promote to active AURA research hypothesis**

## 7. Embodiment transfer remains important but should be tested modestly

Relevant signals include:

- Rho and embodiment midtraining/adaptation;
- human-behavior pretraining directions such as Light-O1 and Figure;
- tactile/visual-tactile transfer;
- bimanual and multi-arm work.

### AURA interpretation

The research question is not "can a giant model train on every robot?"

It is:

> **What knowledge transfers across embodiments, and what must remain embodiment-specific?**

AURA should eventually test this with small, controlled end-effector or robot-body changes.

**Decision:** **READ/WATCH; selective reproduction later**

# Architecture implications for Branch 02

1. Treat DynaHarness as an external architecture competitor/comparison.
2. Do not claim novelty from "policy + verification + recovery" alone.
3. Investigate whether recovery should be hierarchical across control, skill, subtask, and task timescales.
4. Keep world models bounded to roles that can be experimentally justified.
5. Keep memory as an open functional decomposition problem.
6. Separate recovery from persistent learning.
7. Preserve AETHER as a capability/interface framework until ablations support stronger commitments.

# Experiment implications for 06

Highest-value future controlled experiments:

1. governed execution ablation;
2. failure-localized data acquisition;
3. bounded world-model action selector/verifier;
4. recovery-to-learning;
5. memory-type ablations;
6. hierarchical recovery under injected failures;
7. cross-embodiment transfer with a small controlled embodiment change.

# Final takeaway

DynaHarness is not a reason to abandon AETHER.

It is a reason to stop treating broad architecture intuition as a contribution by itself.

AURA now needs to answer:

> **Which capability boundaries, memory structures, predictive interfaces, and recovery/learning mechanisms measurably improve autonomous manipulation — and under what conditions?**

That is a stronger and more defensible research program than competing to draw the largest architecture diagram.
