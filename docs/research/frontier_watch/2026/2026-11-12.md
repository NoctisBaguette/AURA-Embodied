## Executive judgment

The most important change is **not one more architecture block**. Three independent new claims challenge how we decide whether VLAs genuinely generalize: **AMP1's generalist coding-agent approach** competes with specialist VLA/WAM policies; **How Much of Your VLA Is kNN** reports very strong *retrieval-only* action reuse; and **Is Your Robot's Memory Just a Clock?** demonstrates that time-sampled memory can mistake an idle interval for task progress. The strongest low-cost research value may be **transfer controls, negative controls and fair baseline comparison**, rather than adding an external memory or world-model module.

**RoboACE** adds explicit adversarial curriculum evolution around frozen models and overlaps with RoboArchitect/DynaHarness-like self-improving execution systems. **OopsieRecover** examines whether semantic corrective knowledge transfers with few demonstrations. **A sensor-return-adapter paper** directly illustrates environment/hardware adaptation at low local-data cost. **Elastic-WAM** and a BEHAVIOR Challenge release provide alternative compute/runtime routes, rather than proof that online imagination is mandatory.

**Current AURA direction:** keep multiple viable technical configurations and focus on transfer across objects, scenes, sensing, data and embodiments under bounded adaptation/compute cost. This is consistent with the existing architecture and the newly published [research-workbench proposal](../../coordination/AURA_Research_Workbench_Proposal_2026-11-12.md), **not** a new Core-approved architecture.

**Execution:** preserve existing M9a commissioning and Core gate. Current inspected experiment branch `06-01/aether-cl-m0` head `cd8185dbe36676c1edd90031e13a105795b617d5` is unchanged since prior watch. Main contains architecture/coordination; branch contains M0–M8 evidence and M9a engineering. The branch record **does not establish** native camera neutrality or accepted nonprivileged verification; **Core continuity v0.3 and the November 12 resume authorization have explicitly lifted the operator pause for the already-approved commissioning only**; live server health remains unverified. **No new experiment is started or authorized.**

## 2. Highest-signal new findings

### A. AMP1 — On Agentic Manipulation Policies (November 6 v1)

**Primary:** [arXiv:2611.09892v1](https://arxiv.org/abs/2611.09892); [official project](https://apple-aiml-research.github.io/ml-amp/); [official source](https://github.com/apple-aiml-research/ml-amp), README blob `00fd874b5aa31d0c5dcb350a031451b80318df98` inspected November 12.

**What happened?** AMP1 uses a generalist reasoning/coding model to command a robot through sensing, perception, collision-checked motion and gripper tools rather than requiring a task-trained VLA action predictor. Authors report RoboLab-120 zero-shot **85.6%** versus VLA **49.2%** and WAM **42.9%**, plus **104/108** successful real trials across 12 tasks/three robot instances. Persistent agent memory reportedly reduces RoboDojo bimanual failure rate **4.6×** versus zero-shot. The public repo includes a reproducibility guide and declares use of **H100 80GB** and external model APIs in its reported simulator runs.

**Why/capability?** Strong alternative to the assumption that the primary policy must be an end-to-end VLA. It combines active information gathering, explicit API contract, episode-scoped code and potentially experience reuse.

**AURA care:** **DEEP DIVE; MONITOR/BACKLOG**; direct prior-art pressure alongside RoboArchitect, DynaHarness, HELM, CRIS-0, RoboDoctor and RoboAuto. **Critical comparator caveat:** the author project describes simulation pausing while the generalist model reasons; simulation control time is not necessarily comparable to a real-time streaming policy. Count wall-clock/tool/API spend, input sensing privilege and safety/latency constraints before recommending it.

**Possible improvement/reproduction:** source-only adapter/permission-model review first. Later, one *matched* task comparing controller, pretrained policy and agentic tool harness with identical observations, wall-time/resource ceilings and audited outcome predicates—only after Core approval. Do not install this H100/API-oriented stack into frozen M9a.

### B. How Much of Your VLA Is kNN (November 9 v1)

**Primary:** [arXiv:2611.13160v1](https://arxiv.org/abs/2611.13160). The paper's advertised code URL [sereact/lerobot_knn](https://github.com/sereact/lerobot_knn) returned **GitHub 404** from direct repository-file lookup on November 12; no runnable release confirmed.

**What happened?** Nearest-neighbor demonstration retrieval followed by reusing action chunks reportedly reaches **91.7% LIBERO** success **without policy training**, with comparatively small performance drop under LIBERO-Plus shifts. Authors examine nine public VLAs and propose Local Action Consistency (LAC): whether nearby representation-space states imply similar actions.

**Why/capability?** A powerful *negative control* for claims that benchmark success necessarily demonstrates learned reasoning, memory or generalization. Also suggests low-compute retrieval and representation-quality study.

**AURA care:** **DEEP DIVE; NEXT-CHECKPOINT design reference** (not a new active experiment). **Possible improvement/reproduction:** after artifacts/data splits are established, compare nearest-demo retrieval, frozen VLA and identical VLA with a selected AURA mechanism on held-out objects/scenes; deduplicate trajectories and audit training-test overlap, state/action normalization, control timing and action-source diversity. Retrieval may be strong inside familiar task distributions and still fail at genuinely new situations; do not conclude 'all VLAs are just kNN'.

### C. Is Your Robot's Memory Just a Clock? (November 10 v1)

**Primary:** [arXiv:2611.14488v1](https://arxiv.org/abs/2611.14488).

**What happened?** In RoboMME counting tests, null events (brief pause or harmless wrist movement) leave physical task progress unchanged but cause a released time-indexed memory VLA to infer **phantom progress**. Authors report task successes falling **47/50→16/50** and **44/50→10/50**. Withholding null-event frames from memory restores success; changing timestamps alone also changes behavior. Merely removing time embeddings is insufficient; **event-indexed memory** recovers at least half the loss without retraining under the studied conditions.

**Why/capability?** Direct, falsifiable demonstration that time, frames and completed physical effects are different variables. A longer memory buffer can make an agent **less correct**.

**AURA care:** **DEEP DIVE; strongest refinement of the already existing post-M9a evidence-freshness/invalidation candidate.** **Possible study:** insert idle observations, delay, repeated views and harmless control motions; keep true task state fixed; compare time-indexed, event-indexed and explicit-evidence progression with matched observation budget. Report false completion, unnecessary intervention, detection delay and real task success. No modification to frozen M9a protocols/seeds.

### D. RoboACE — adversarial co-evolution of curriculum and execution (November 9 v1)

**Primary:** [arXiv:2611.13034v1](https://arxiv.org/abs/2611.13034).

**What happened?** Alternately revise a **practice/curriculum harness** that seeks informative weaknesses and an **execution harness** that develops reusable fixes around frozen foundation models. Fixed evaluation snapshots separate challenge selection from deployment. Authors report **74.0% LIBERO-PRO**, **+15.0 points** over the initial deployment and **+13.5** over direct VLA control, under their comparisons.

**Why/capability?** Failure-driven learning depends on **which failures are selected for practice**, not just how the policy is repaired. A direct extension of RoboArchitect/SEAR/DynaHarness prior art; raises novelty and equal-practice-budget questions.

**AURA care:** **DEEP DIVE comparator; MONITOR/BACKLOG**. **Possible test:** static vs actively selected practice at matched episodes, tool calls, human assistance and fixed held-out test conditions; track forgetting and regressions. Official runnable artifact and model/tool budget were not confirmed here; no full reproduction proposed.

### E. Next-best-view world-model adaptation to a real sensor (November 9 v1)

**Primary:** [arXiv:2611.13229v1](https://arxiv.org/abs/2611.13229).

**What happened?** A pretrained world predictor is held fixed; a **small sensor-return adapter** learns which predicted surfaces produce usable depth returns in the deployed structured-light system. In one real-robot 3D reconstruction comparison, authors report higher measured coverage with **60% fewer captures** than nominal view selection.

**Why/capability?** A concrete example of **scene/sensor-domain migration with a small local calibration budget**. The critical problem is not just simulated surface geometry: the physical camera may fail to observe it.

**AURA care:** **DEEP DIVE concept; NEXT-CHECKPOINT design alternative only**. **Possible test:** once a sensor interface is accepted, compare fixed depth-validity assumptions against calibration-derived dropout predictions under changed material, viewpoint and lighting; measure actual validity, surface coverage, capture cost and calibration effort. This is **3D reconstruction**, not direct evidence of better manipulation task success. No new sensing action added to M9a.

### F. OopsieRecover — transferable semantic corrections (November 5 v1)

**Primary:** [arXiv:2611.08462v1](https://arxiv.org/abs/2611.08462); [author project](https://robin-lab.cs.utexas.edu/oopsierecover/).

**What happened?** Infer the semantic intent of a handful of corrections using abductive reasoning; express it as spatial conditions and costs that steer future actions. Authors report improvements over six tasks across changed object poses/scenes/related tasks without repeated corrective demonstrations for every variation.

**Why/capability?** Turns human repair into a candidate **transferable constraint**, contrasting raw DAgger replay, scoped skills and implicit policy updates. **AURA care:** **READ→DEEP DIVE; BACKLOG**. **Possible test:** same demonstration and intervention budgets, compare raw imitation, retrieved corrections and conditional spatial costs on held-out objects/scenes; report adaptation/regression. No local code or benchmark download verified.

## 4. Competing hypotheses and practical routes

**H-A — Event-grounded task progress.** Memory indexed by time may fail under pauses and unobserved non-events. Explicit evidence-linked state or event-indexed learned memory might reduce phantom progress. But external graphs are **not mandatory**: a simple event counter or learned representation might suffice. Test a no-extra-memory baseline as well.

**H-B — Cheap action retrieval as a necessary control.** Strong kNN performance means high benchmark success may reflect local demonstration coverage rather than broad transfer. For migration studies, specify **object, environment, dataset, hardware and embodiment** axes separately, including distance from demonstrations and adaptation budgets. A retrieved chunk can be strong yet unsafe or infeasible under a new embodiment.

**H-C — Agentic tool policies are credible alternatives.** AMP1 and BEHAVIOR's hybrid solution should compete on actual cost/latency/privilege with specialist policies. The contrast is not 'generic agents are always better'. Source access, active perception, simulation pausing and external model requests strongly affect the comparison.

**H-D — Small adapters can matter more than giant pretraining.** The sensor-return study and OopsieRecover provide concrete ways to adapt with limited local evidence. MR0/NEO/Open-HumanWAM raise the ceiling for large systems but are not direct instructions to reproduce their training.

These hypotheses support the user's open-route, transfer-first collaboration approach, without altering existing architecture authority. A future research workbench can register candidate source IDs `FW26-11-12-AMP1`, `-KNN`, `-CLOCK`, `-ROBOACE`, `-SENSOR`, `-OOPSIE` and attach each to the same transfer/compatibility criteria and explicit evidence level. These are **proposed library IDs**, not created platform records.
