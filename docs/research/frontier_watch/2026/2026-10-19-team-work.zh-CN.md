## WP1 — 有边界的架构比较：证据时效性与干预

**建议负责人：**研究/架构方向队友。**评审：**Core/02。**状态：**拟议，未分配。

**服务的决策：**D2——在不扩大 M9a 范围的前提下，选择下一个可检验问题。

**问题：**当前 AURA 接口已经覆盖证据时效性（evidence freshness）、任务状态修订和干预选择的哪些部分？增加哪一个对照最能区分不同方案？

**输入：**当前 `ARCHITECTURE.md`；`06-01/aether-cl-m0` 分支上的 M9a commissioning-start 记录；证据条目 E1/E2/E3/E5/E9。优先阅读 REMM、RESCUE、TacitVLA。Fast-VLA/ForkCast 只读比较所需部分；这项任务不是所有模型的综述。

**交付物：**一份 2–4 页比较说明，以及一张简洁的来源—主张表。分配后的建议存放路径：`docs/research/coordination/team_returns/FW-20261019-WP1.md`。

**必备内容：**输入信息及特权信息边界、状态有效性语义、哪些过程必须阻塞动作、更新时机、可选干预、证据强度、受控基线、局限。区分 AURA 已有决策与本次新建议。

**验收条件：**

- 每个支撑主要结论的事实都指向一手来源及对应章节；未获支持的细节明确标为未知。
- 在相同传感输入下，至少比较一种保持现状的简单方案和一种拟议替代方案。
- 给出一个优先研究问题、一个拒绝/暂缓某替代方案的理由，以及能推翻首选判断的可观察结果。
- 明确是否有发现会使当前 commissioning 工作失效；不能只写“需要重新设计整个架构”。

**估计工时：**4–8 小时集中评审。**依赖：**能够访问来源材料及当前范围文档；无需 GPU。

**不包含：**采纳新架构、认证论文创新性、编写通用状态本体、激活 02W，或执行原生仿真。

## WP2 — 传感器/证据接口与测试样例检查

**建议负责人：**传感/软件方向队友。**评审：**06-01 检查兼容性，Core 检查语义。**状态：**拟议准备工作，未分配。

**服务的决策：**D1——帮助完成现有传感器 commissioning/评审；不改变实验条件地为 D2 做准备。

**问题：**如何表达观测的有效性与来源，同时避免泄漏仿真答案，或把缺失证据误判为物理失败？

**输入：**实验分支上的 `AURA_M9a_Commissioning_Start_v0.1.md`、`AURA_M9a_Camera_IO_Commissioning_v0.1.md`；已接受的 M8/M9a 输入边界；工程负责人提供的真实允许数据包/字段样例。不得凭空发明新的原生 API。

**交付物：**字段级接口契约；若获准在独立准备分支工作，再提交测试样例（fixtures）及对应测试。建议评审记录：`docs/research/coordination/team_returns/FW-20261019-WP2.md`。最终代码位置由 06 决定，不由本报告决定。

**待评估而非自动新增的最小字段：**观测时间、到达时间、传感器身份/标定、实测机器人状态、证据有效性、预期效果标识、允许的命令上下文。记录需区分观测支持的真/假、证据未知，以及尚未到判定时机的 pending。必须明确单位、坐标系和时间基准。

**验收条件：**

- 给出现有数据包的字段映射，并明确禁止输入的真值、接触、奖励、实验条件和评估器字段。
- 测试样例覆盖有效观测、缺失数据、过期时间戳、乱序到达，以及真实相互矛盾的证据。
- 不得用命令的预期效果或模型生成的记忆文字，替代实测物理结果。
- 与已接受接口不同的行为必须单独列为尚未批准的变更；现有执行器与恢复规则保持不变。
- 返回材料准确区分“检查过”与“执行测试过”。合成测试通过不等于原生相机不扰动性验证通过，也不等于验证器准确率已获证实。

**估计工时：**取得真实数据包样例后，4–8 小时。**依赖：**样例/字段访问权限，以及 06 对准备分支和测试范围的认可。可能可用 CPU 完成样例测试；原生 GPU 工作不在本包范围内。

**不包含：**为提高分数修改传感阈值、新环境重置、新外力条件、更换策略、新恢复行为、正式 M9 评测，或编辑冻结的执行代码。

**建议负责人：**模型/运行时方向队友。**评审：**06-HQ 与 Embodied-AI 对应基线负责人；最终选择由 Core/HQ 决定。**状态：**未分配，仅做可行性评估。

**服务的决策：**D3——选择成本可承受、可复用的基线，或者得出“两个新候选都不应替代当前工作”的结论。

**输入：**E5/E6 的官方仓库、现有可用公开策略资产、Embodied-AI 当前基线计划，以及用户确认的计算/存储预算。优先复用兼容工作，而非自动再搭一套仿真器。

**交付物：**一张可行性对照表，加一份隔离环境搭建/冒烟测试计划。建议路径：`docs/research/coordination/team_returns/FW-20261019-WP3.md`。

**比较对象：**

- 已有兼容基线（如有）。
- `Garfield-kh/FastVLA`：每回合一次任务缓存 + 在线执行网络。
- `jiuyixu25/FastVLA`：在受支持 VLA 骨干上进行自适应视觉 token 裁剪。

**验收条件：**

- 分别记录准确论文 ID、官方仓库提交、检查点身份/访问状态和许可依赖。
- 将动作表示、维度、控制频率、相机布局、本体感知输入与任务环境映射到候选基准；不得假定 ALOHA 关节动作策略可以直接接入 Panda 位姿控制器。
- Python/Torch/CUDA/仿真器依赖与冻结 AURA 环境隔离；不得仅凭论文 README 就要求修改系统驱动。
- 区分峰值/预填充/在线 GPU 内存、存储和下载可行性；未实测需求标为作者说明或未知。
- 计划规定一个小型冒烟测试和一个基线—干预对照，不直接启动全套训练或评测。
- 结论必须为 GO、带具体前提的 CONDITIONAL GO，或 NO-GO，并说明为何现有基线可能更合适。

**估计工时：**来源/资产可行性检查 3–6 小时；安装和原生执行须获批后另行预算。

**依赖：**真实计算、存储、网络条件，以及模型访问权限。在线执行网络较小不代表初始化阶段不需要大模型资源。

**不包含：**默认运行两套完整基准、把宣传速度提升当作 AURA 结果、混淆两个 FastVLA 方法，或升级原生实验环境。

## WP4 — 失败/证据标注与评估规范

**建议负责人：**评估/数据方向队友。**评审：**06 证据评审者与 Core/02。**状态：**拟议，未分配。

**服务的决策：**D1/D2——提供能够区分感知问题、物理执行问题与任务层失败的评估材料。

**输入：**工程负责人提供的允许使用的保留相机/回合证据、现有评分定义、E7 LABIT 的依赖关系视角，以及本包列出的证据限制。Anvil 仅为可选一手来源阅读线索，不是必需模型。

**交付物：**标注指南、在有真实录像时完成的小型复核样本，以及指标字段规范。建议路径：`docs/research/coordination/team_returns/FW-20261019-WP4.md`，并链接不含敏感信息的清单。

**需区分的标签：**观察到目标效果已实现、观察到目标效果被破坏、证据不足/遮挡、证据过期、预期动作尚未到判定时机、先前条件失效、错误宣布任务完成。分别记录证据时间与决策时间。不能凭直觉给不可见状态下结论。

**验收条件：**

- 每个标签都有可操作规则和示例；推断原因与直接观测到的效果分开。
- 小样本经过独立复核并保留分歧；若没有数据，则交付字段规范和明确标为合成的示例，不声称已经标注原生数据集。
- 特权参考标签、场景/种子标识与实验条件只能供评估器使用，不得进入部署输入。
- 指标计划包括覆盖率/未知率、错误成功判定、错误干预、检测延迟和端到端时延；任务成功与控制器阶段完成继续分开统计。
- 扩大样本前明确标定/开发/评测边界，以及清单和哈希溯源。

**估计工时：**取得可用证据后 3–6 小时。**依赖：**真实帧/日志及访问、共享权限；不包含新采集活动或硬件采购。

**不包含：**静默修改旧标签、编造不可见物理事实、把截图当作完整回合证据、在未来评测场景上调参，或未经批准使用新实验种子采集数据。

## 4. 如何把这些交付物转成开发

WP1 返回最值得检验的最小决策；WP2 返回兼容的证据接口/测试边界；WP4 返回衡量它的方法。WP3 可以准备相对独立的未来学习策略基线，但不阻塞当前固定控制器研究。

Core 只将已经接受的部分组合进一个有边界的实验协议。新原生对照前，协议必须写明：假设、任务、不变基线、变化机制、输入与特权边界、数据划分/种子、指标、资源预算、停止条件和准确证据产物。批准与执行是两件事，均需留记录。

优先在约定里程碑做一次短集成评审，不要求所有人读完所有论文。否定可行性的结论或推翻假设的实验也是有效返回。

## 6. 队友返回材料的统一格式

1. 获分配的问题与范围、实际负责人、评审者、状态。
2. 输入与使用的准确来源/代码/数据版本。
3. 修改或检查了什么，哪些内容保持不变。
4. 已交付产物的路径/提交。
5. 真正执行过的检查、原始证据和失败记录；计划中的测试必须单独标明。
6. 结果、不确定性、局限与被排除的替代方案。
7. 具体建议：集成、再完成一个明确检查、暂缓，或停止。

只有当另一位成员/另一个聊天能够把主张追溯到产物，并理解其支持什么决策时，评审才算形成有效交接。这个标准使 GitHub 成为协作工作区，而不只是论文清单。
