## 4. Mechanisms worth considering

### A. Evidence freshness and nonblocking reasoning

**What happened?** REMM distinguishes retained evidence from revisable conclusions; TacitVLA separates reasoning supervision from waiting for current generated reasoning; the once-per-episode Fast-VLA caches task context while its actor still consumes current observations. Sources E1, E3 and E5.

**Why does it matter?** These are different answers to different costs. Reducing reasoning latency does not remove the need to know whether the relevant belief is current.

**Capability represented:** task-state maintenance, temporal context, selective computation.

**Does AURA care?** DEEP DIVE, scoped to the existing sensing interface; next-checkpoint candidate, not a new memory module inside M9a.

**Possible reproduction/improvement?** After the current baseline is accepted, compare permanent completion flags, unconditional refresh and evidence-linked invalidation using the same observations and executor. Separate unavailable evidence from observed contradiction. First test decision traces on retained data; authorize new disturbances/closed-loop trials separately. A proposed asynchronous bookkeeping process must never be treated as an already-verified physical outcome or replace a synchronous safety gate without evidence.

### B. Intervention value before elaborate learned recovery

**What happened?** RESCUE tests whether acting on an alarm reduces completion cost; ForkCast compares alternative interventions using predicted futures. Sources E2 and E9.

**Why does it matter?** A better detector can still lead to worse behavior when unnecessary resets are expensive. A learned predictor is not necessary to begin measuring this problem.

**Capability represented:** recovery selection and active information acquisition.

**Does AURA care?** DEEP DIVE; keep as a later experimental candidate rather than adding more intervention types to the frozen M9a matrix.

**Possible reproduction/improvement?** A later checkpoint study can compare continue, reobserve and the existing bounded retry. Restore simulator state, policy state, caches, controller phase and RNG consistently. Count observation/motion/reset/inference costs; distinguish counterfactual experimental access from information available to the deployed controller. Saved-state branching feasibility must be demonstrated, not assumed.

### C. Efficient learned-policy baseline: distinguish the two FastVLA systems

**What happened?** One repository uses a one-time task-context encoder with a small online actor; the other modifies token selection inside compatible VLA backbones. Sources E5 and E6.

**Why does it matter?** They are not competing implementations of the same intervention. Token pruning is potentially a small matched change to a compatible learned baseline; the cached-context architecture is a separate baseline with a different training/runtime interface.

**Capability represented:** efficient perception-to-action execution.

**Does AURA care?** READ / reproduction-feasibility candidate. A suitable bounded teammate task is to determine what actually runs with our resources.

**Possible reproduction/improvement?** Prepare an isolated environment and artifact plan first. The once-per-episode repository documents a different Python/Torch stack from the existing AURA experiment; its small online memory number is not whole-system peak memory. For pruning, verify access to the underlying checkpoint and control interface, then propose a full-token versus pruned comparison with identical seeds and timing accounting. Do not install either stack into the frozen native environment. Reuse Embodied-AI's baseline work where compatible.

### D. Action-aware retrieval: promising, but not a ready substitute for sensing

**What happened?** Robota-Embed aligns current vision/language/action context with useful recorded continuations. Source E4.

**Why does it matter?** A visually similar episode can be the wrong stage or require a different next action. However, a retrieval system also needs consistent action coordinates, timestamps and episode boundaries.

**Capability represented:** episodic experience selection and context adaptation.

**Does AURA care?** DEEP DIVE conceptually; implementation backlog until corpus/interface and artifact availability are established.

**Possible reproduction/improvement?** First define a small offline failure/recovery retrieval evaluation: visual-only versus vision-language versus action-aware keys, with held-out episodes and no future-outcome leakage in queries. Policy performance requires a later compatible consumer, not just high retrieval recall. A paper's task-local context improvement is not automatically reusable cross-task learning.

### E. Evaluation work that teammates can contribute without a new model

**What happened?** LABIT examines how assembly errors propagate across operations. Anvil's upstream report proposes separating grounding, relations and action interpretation, but its primary details remain a targeted review task here. Sources E7 and E8.

**Why does it matter?** We can improve diagnosis and dataset specifications before reproducing large architectures.

**Capability represented:** failure localization and task-level reliability evaluation.

**Does AURA care?** READ / bounded evaluation-design work.

**Possible reproduction/improvement?** Define labels for the earliest unsupported precondition, incorrect state estimate, failed effect and false task-completion declaration. Keep model inputs separate from evaluator-only labels. Build an annotation guide and small double-reviewed sample from existing permissible evidence; do not buy assembly hardware or claim physical results from the design.

## 5. Architecture choices for Core/02

This packet favors no mandatory new module. Compare these alternatives explicitly:

| Choice | Simple alternative | More structured alternative | Evidence that would justify added complexity |
| --- | --- | --- | --- |
| State maintenance | Current observations / existing temporal verdicts | Evidence-linked validity and dependency records | Fewer stale completion decisions without excessive unknowns or false alarms |
| Reasoning cadence | Existing fixed schedule | Boundary/event-triggered or asynchronous bookkeeping | Lower measured latency without delayed hazard response or stale task goals |
| Recovery selection | Existing bounded retry rule | Cost-aware selector, eventually predictive | Lower completion cost and preserved healthy cases under matched budgets |
| Experience reuse | No retrieval / small rule-based library | Learned action-aware retrieval | Held-out relevant retrieval plus downstream utility beyond extra context/trials |

Prior-art overlap changes how a contribution is described; it does not erase the value of AURA's instrument or justify a weekly implementation restart. A claim that one mechanism is novel requires a method-level review, not the similarity of architecture diagrams alone.
