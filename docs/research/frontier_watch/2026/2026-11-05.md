## Executive decision

**No experiment-scope change.** The strongest new competitive pressure is **RoboArchitect (automatically evolved policy harness + persistent memory), DiMuRe (diagnosis-guided multilevel recovery), and REA (bounded asynchronous policy routing)**. These join DynaHarness, HELM, CRIS-0, LOGIV, RoboDoctor and RoboAuto as direct counterexamples to claiming a generic policy+memory+verifier+recovery combination as novel. **RoboArchitect's public code is real, but executing its multiple policy/benchmark environments and coding model is not a cheap independent reproduction.**

The strongest architectural tension is between **HiLo-WAM's two-timescale future streams**, **DreamFree's single-pass future-representation distillation**, **ARP's age-aware asynchronous semantic cache**, and **geometric abstraction's locally refreshed explicit RGB-D facts**. They offer multiple, potentially cheaper implementations of state and prediction; none proves every layer must be present. **LoopQ** further shows apparent inference optimization may *slow* real control or hurt perturbed success. The priority remains measured effect correctness and reliable timing, not largest architecture diagram.

**Continue the authorized M9a camera/Vulkan/sensor-I/O commissioning only** (subject to operator pause). Next scientific candidate remains **evidence freshness and task-state invalidation after accepted non-privileged sensing**. This report nominates **zero new active experiments**.

## 2. High-signal papers — mechanism, value, test

### A. RoboArchitect — automatically evolving the harness around a frozen VLA
**Primary:** [arXiv:2610.42141v1, Oct 30](https://arxiv.org/abs/2610.42141); [author project](https://roboarchitect-ai.github.io/); [official GitHub](https://github.com/roboarchitect-ai/RoboArchitect), README blob `fcaf8b83b2ab8973619e9b1cc73705840763ba82` inspected Nov 5.

**What happened?** A coding model reads failures and rollout traces, revises policy-routing/control code and persistent memory, retains improving revisions, then evaluates on unseen scenes/tasks without updating policy weights. **Reported** mean successes: unseen scenes **9.7%→43.3%**, unseen tasks **12.7%→40.2%** across heterogeneous setups, not uniform per-task gains (one benchmark loses slightly). Public code requires multiple external benchmark/policy/tool environments, model checkpoints and **Claude Code**; a README is not a runnable AURA install.

**Why/capability?** Automated harness synthesis, recovery skill invention, procedural memory and transfer. **AURA care:** **DEEP DIVE; MONITOR/BACKLOG**, strongest novelty threat this week. **Possible test/improvement:** after a compatible policy baseline, freeze policy and compare scripted harness, one-shot generated harness, iterative generated harness and a human-selected minimal correction under **matched rollout/coding/tool budgets**, independent held-out scenes and regression checks. Do not call improvement “autonomous learning” if hidden external models/tool calls or selected retries explain it.

### B. DiMuRe — diagnosis-guided multilevel recovery
**Primary:** [arXiv:2611.04226v1, Nov 3](https://arxiv.org/abs/2611.04226).
**What happened?** Phase-specific evidence and preconditions select **reuse vs predefined recovery skills** (including VLA grasping); after program exit, an MLLM can generate corrective code. Local effect checks validate steps. Introduces **LIBERO-Disturb**. On **801 scheduled development disturbances**, author reports **77.65%** Local DiMuRe complete success vs **58.68%** original under same physical-step allowance; **81.90%** Full DiMuRe adds terminal replanning, an **extra step allowance** and early handoff. Do **not** equate full and local budgets.
**Why/capability?** Direct prior art for failure-localized, minimum-change multi-level recovery. **AURA care:** **DEEP DIVE; BACKLOG**, not M9a insertion. **Possible test/improvement:** same-policy/same-budget local-retry vs diagnosis-guided hierarchy with verified cause/effect, false interventions and healthy-case preservation; disclose human/MLLM code budget. Public runnable LIBERO-Disturb artifacts not checked.

### C. REA — routed asynchronous brain/cerebellum runtime
**Primary:** [arXiv:2610.42053v1, Oct 30](https://arxiv.org/abs/2610.42053).
**What?** Multi-level runtime where running policy never waits for slow brain; policy success history, boundary-triggered judge and shared-budget escalation route actions/recovery. Author reports **95.9% vs 94.7%** best single policy over **3,000 LIBERO-Pro test episodes**, with **25% fewer control steps, 17% less control time**; separate RoboTwin evaluation uses different policies and 100 episodes. **Why/capability?** Route memory and bounded intervention selection without blocking control. **Care:** **DEEP DIVE** as competitor; **BACKLOG**. **Possible test:** measure *exactly* when the high-level judge is invoked and how silent failures/false triggers behave; same executor, latency accounting and intervention budget. Code runnable status not established.

### D. Asynchronous Robot Policies (ARP) — semantic age is an explicit input
**Primary:** [arXiv:2611.05155v1, Nov 3](https://arxiv.org/abs/2611.05155), [author site](https://arp.insait.ai/) states **code/models soon** as of Nov 5.
**What?** Slow VLM writes semantic memory; fast actor reacts to current camera views, trained with stale semantic inputs and execution-delay conditioning. Author project: displaced-target simulation **51.5% vs 9.5%**; with VLM update every 4 seconds LIBERO success **79.0% vs 45.3%**. **Counterevidence:** broad RoboLab score **20.0 vs 37.9%** for a competing baseline. **Why/capability?** Time-aware policy, latency/state-staleness tradeoff. **Care:** **DEEP DIVE concept; BACKLOG**. **Possible test:** old/fresh semantic memory crossed with fast camera input, delayed observations and changed instruction. Physical-effect verifier still needs separately trustworthy evidence. It is *not* evidence a universal asynchronously updating planner always wins.

### E. HiLo-WAM — two timescales inside one WAM
**Primary:** [arXiv:2611.05023v1, Nov 3](https://arxiv.org/abs/2611.05023).
**What?** Sparse long-horizon task-evolution stream and dense local-contact stream jointly condition actions, with dynamic denoising/skip compute. Authors report **93.70% RoboTwin 2.0**, **17.43 RoboDojo long-horizon progress** and **2.93×** progressive inference speedup under their settings. **Why/capability?** Task evolution and contact dynamics need different temporal bandwidths; separate **functional timescales** do not force separate memory databases. **Care:** **READ→DEEP DIVE; BACKLOG**. **Possible test:** isolate long-history vs short-contact signals and report inference latency and changed-goal responsiveness; do not migrate M9a to a WAM.

### F. DreamFree — future-representation distillation instead of online imagination
**Primary:** [arXiv:2611.04527v2, Nov 4](https://arxiv.org/abs/2611.04527); [author project](https://harryjo97.github.io/dreamfree/) says **code soon**.
**What?** Frozen video teacher supervises predictive visual features from current observations; fast action decoder needs no generated future frames at inference. Author reports **71.7% RoboCasa**, **64% vs 56%** on **50** real-world DROID tasks/trials vs DreamZero, and **~91 ms/action chunk on H200**. A **14B** backbone is not a low-cost reproduction. **Why/capability?** Strong new support for JAM/PDRVLA's idea: physical prediction can be trained into an action pathway, not necessarily supplied as an online video stream. **Care:** **DEEP DIVE conceptual; BACKLOG**. **Possible test:** once learned baseline is ready, action-only vs frozen-future-feature auxiliary loss vs runtime candidate predictor with matched model/data and actual latency, noting teacher training budget.

### G. Geometric abstraction — rebind symbols to observed RGB-D
**Primary:** [arXiv:2611.05058v1, Nov 3](https://arxiv.org/abs/2611.05058); [author project](https://geometric-abstraction.github.io/); [public repo](https://github.com/Spectraorder/geometric-abstraction) (MIT; independent Python 3.14/MuJoCo stack; model-driven reproduction requires Codex/model account).
**What?** Local calibrated RGB-D estimates object parts and metric residuals, exposes **observed/inferred/unavailable** typed facts to slower LLM decisions; refreshes pose from evidence rather than trusting command history. Authors report bridge-tower **28/50 vs 12/50**, relocation **42/50 vs 15/50** paired layouts, 33.3% shorter ring completion at matched task under their evaluation. **Why/capability?** Extremely close to AURA's intended *nonprivileged state-transition interface*, a specific stronger comparator than a generic symbolic graph. **Care:** **DEEP DIVE; NEXT-CHECKPOINT design reference, not a newly authorized experiment.** **Possible test:** at an approved later checkpoint, compare raw RGB-D verifier, evidence-aware geometric residuals, and a task-state overlay with identical camera data, missing/occluded cases and exact false-completion metrics. Reuse read-only tests before any simulator deployment.

## 4. Architecture / novelty implications for 02

- **Red-flag novelty overlap:** DynaHarness + LOGIV + **DiMuRe** already cover support dependencies and bounded local recovery; **RoboArchitect** adds *automatic* harness revision with persistent skills; **REA** combines routing and latency-aware escalation. Do not claim “agent + verifier + recovery + memory” is inherently novel. Compare success with *identical* sensing, baseline actions, tool budgets and held-out environments.
- **AETHER hypothesis challenged:** **DreamFree/JAM/PDRVLA** argue a policy can learn future-relevant representation *without* online future video; **HiLo-WAM** argues joint multiscale future modeling can still help; **ARP/REA** argue slow reasoning can be asynchronous but must confront stale semantics; explicit geometry argues for inexpensive observed state. No single implementation wins across these incompatible comparisons.
- **Most useful AURA-specific discriminant:** can measured, timestamped nonprivileged RGB/RGB-D/proprioception distinguish observed intended physical effect, unknown/occluded evidence and invalidated prior completion **without privileged labels or additional harmful interventions**? Keep training complexity out until this boundary is validated.
