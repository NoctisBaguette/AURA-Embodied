The upstream model card's high RoboTwin numbers describe that separately post-trained model. The retained competition briefing requires base initialization/clean-only data and prohibits using the already RoboTwin-post-trained model as the competition initializer. Do not substitute it as a submission shortcut. Current official rule page retrieval exposes only part of the text; the explicit prohibition here is attributed to the supplied Day0 rules record.

Deadline decision: prioritize a measured candidate result and complete export over another unexamined training cycle. The existing trainer supports STOP_TRAIN: after the current completed update it runs generated-action diagnostics, saves/restores the full checkpoint and proceeds to the existing32candidate episodes. Captain-only optional control is delivered separately. This intentionally forgoes remaining planned updates; it is not a temporary pause that auto-resumes. It starts no new GPU process itself and does not change the success predicate, seeds, action mapping or timeouts. Saving/evaluation can still fail; no native result is claimed from the CPU control tests. If candidate is already evaluating, the control is a no-op.

Candidate decision: inspect official success AND failures/videos across the same panel. Improvement is only pilot evidence; select no checkpoint automatically. If it remains weak, test one concrete hypothesis against the recorded input/output/visual boundary before spending another training budget. Never manufacture a nonzero score, soften success, skip failed tasks, or choose different weights per task.
